# STM32F407 板级接入

仓库保留硬件型号。CubeMX 工程负责外部晶振、引脚复用、连接器和板上器件的实际映射。应用依赖 STM32CubeF4 HAL、FreeRTOS 和 [依赖版本](upstream.md)。

## CubeMX

1. 按实物选 STM32F407 完整料号与晶振，配置 48 MHz 系统时钟。启用 I²C Fast Mode 400 kHz、HC-05 数据 UART 8N1，以及启动按钮、机械编码器 A/B。UART 波特率以手上的模块数据模式设置为准。
2. 根据模块确定 BMI270 地址（默认 0x68，SA0 高时以编译定义 `LP_BMI270_I2C_ADDRESS=0x69` 覆盖）。MAX30102 为 0x57，SSD1306 为 0x3c，DRV2605L 为 0x5a。使用符合各器件电平的模块和上拉，MAX30102 裸芯片 VDD 与 LED 电源分开。
3. 将 BMI270 INT1 接配置为上升沿 EXTI，将 MAX30102 开漏 INT 接下降沿触发的 EXTI 并上拉。两个 EXTI 和 UART IRQ 的优先级须允许调用 FreeRTOS FromISR API。启用 UART IRQ，并保留 Cube 生成的 IRQ handler。
4. 使用 1 kHz、32 位 FreeRTOS tick，抢占式调度，至少 4 个优先级，启用 mutex、动态内存、任务通知、`INCLUDE_vTaskDelay`、`INCLUDE_vTaskDelete` 和 stream buffer。使用 `heap_4` 时可从 16 KiB 堆起步，通过栈和堆水位验证。HAL 1 ms timebase 用独立定时器，SysTick 交给 FreeRTOS。
5. 在 Cube 生成的 CMake 工程中启用 C、CXX 和 ASM。链接 Cube HAL、CMSIS、FreeRTOS Cortex-M4F port，加入 LeapPulse 的固件目录和板级钩子。将 [接线模板](../firmware/stm32f407/cube_hooks.c.example) 的句柄与 GPIO 名换成实际生成值。调用 `start_leappulse()` 后再启动 FreeRTOS。

```cmake
set(LP_BMI270_DIR "/path/to/BMI270_SensorAPI" CACHE PATH "")
set(LP_LVGL_DIR "/path/to/lvgl" CACHE PATH "")
add_subdirectory("/path/to/LeapPulse/firmware" "${CMAKE_BINARY_DIR}/leappulse")
leappulse_attach_app(${CMAKE_PROJECT_NAME})
```

使用 `-Os -ffunction-sections -fdata-sections` 和链接 `--gc-sections`，并确认应用镜像及其初始化数据适合 Flash 槽。应用使用 OLED 的 I1 渲染配置。Windows 上如果 GNU 工具链无法处理路径，使用 ASCII 路径构建。

## Tickless 与 STOP

`configUSE_TICKLESS_IDLE=1` 使用 Cortex-M FreeRTOS port 的普通 tickless idle。要使用 RTC STOP，把该值设为 `2`。在 Cube 中配置 32.768 kHz LSE、RTC 24 小时模式、影子寄存器、异步预分频 31 和同步预分频 1023。启用 RTC Wakeup IRQ，RTC 唤醒计时器由 LeapPulse 独占。在启动 RTOS 前调用 `lp_stm32_stop_init(&hrtc, SystemClock_Config)`。时钟恢复回调必须能在中断屏蔽时运行。

经典 HC-05 的 STATE 接上升沿 EXTI，用于连接事件唤醒。连接期间保留 USART 时钟以免丢数据，只有已接 STATE 且未连接时才进入 RTC STOP。无 STATE 接线时保持普通休眠路径。图中的 RF HOST_WAKE 延迟需要在板上测定。评估最低功耗时要把显示、HC-05、传感器模块和稳压电路计入整板电流。

## 应用与引导程序

从 STM32CubeF4 生成两个工程。应用使用 FreeRTOS，独立引导工程只需 STM32F407 startup、CMSIS 和 HAL Cortex/Flash，替换其生成的 `main.c`。在引导工程 CMake 中引入 `firmware/stm32f407/boot.cmake`，调用 `leappulse_attach_boot(目标)`。

| 区域 | 起始地址 | 说明 |
| --- | --- | --- |
| 引导 | `0x08000000` | 32 KiB，扇区 0–1 |
| OTA 日志 | `0x08008000` | 扇区 2，写入偏移和完成标记 |
| 应用 | `0x08010000` | 192 KiB，扇区 4–5 |
| 暂存 | `0x08040000` | 扇区 6–7，可接收 192 KiB 镜像 |

按表修改各自 GNU linker 的 Flash ORIGIN/LENGTH。应用的 `system_stm32f4xx.c` 要在 `SystemInit` 保持 VTOR 指向应用基址，使用该 CubeF4 版本的 `USER_VECT_TAB_ADDRESS` / `VECT_TAB_OFFSET` 或等效设置。由调试器首次烧录引导和应用。普通 OTA 使用对应用 ELF 执行 `arm-none-eabi-objcopy -O binary app.elf app.bin` 生成的二进制，不包含引导程序。

在实际量产布局上保护引导扇区。Flash 擦除参数面向 2.7–3.6 V 供电的 F407。启用 IWDG 时，按电压、温度和 LSI 容差保证其超时长于最坏单扇区擦除，应用在循环和升级擦除前喂狗，引导复制时也喂狗。默认关闭 OTA 写入权限。板级 `allow_update` 应由本地维护授权打开，OTA CRC 无固件签名语义。

实板验证包括用示波器核对 I²C 与 EXTI，重放已知跳绳次数，检查空载光学信号与佩戴信号，确认 UART 收发和误包重试，以及分别在写暂存区、更新进度和复制运行区时断电。
